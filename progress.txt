2026-07-28 per-browser galleries

CONTEXT
- The Worlds and Systems lists were global: GET /api/worlds and /api/systems
  selected the newest rows with no owner filter, so every visitor saw every world
  anyone had ever saved. Nothing in the schema recorded who saved what.

DONE
- Added a nullable owner_key column plus an (owner_key, created_at) index to both
  worlds and systems. Nullable only for pre-existing rows, which belong to nobody
  and are now reachable by their /w/:slug or /s/:slug link alone.
- Added src/lib/owner.ts: a random base64url key the browser issues to itself and
  keeps in localStorage, with an in-memory fallback for private browsing.
- listWorlds/listSystems/saveWorld/saveSystem now send it as x-owner-key. Fetching
  one thing by slug deliberately does not, so shared links still work for anyone
  and stay immutably cacheable.
- List handlers filter by the key, reject an ownerless POST with 400, and answer a
  keyless GET with an empty list.
- List responses moved from `public, s-maxage=10` to `private, no-store` with
  `vary: x-owner-key`. Deliberate: a shared CDN entry would serve one visitor's
  gallery to the next. Slug routes keep their one-year immutable caching, so the
  performance plan's share-link criterion is unaffected.
- Reworded the Worlds and Systems panel copy from "recently saved" to the
  visitor's own, and said that links still open for anyone.

VERIFIED
- bun run typecheck
- bun run lint
- vitest run: 74 passed, including 6 new owner-key tests
- playwright: gallery degradation and per-browser key isolation both pass
